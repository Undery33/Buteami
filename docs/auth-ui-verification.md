# 계정 UI 검증 기록 — 2026-10-21

관련 작업: [웹 화면 #3](https://github.com/Undery33/Buteami/issues/3), [백엔드 연동 #4](https://github.com/Undery33/Buteami/issues/4).

## 범위

로그인, 아이디 찾기, 비밀번호 찾기, 회원가입 정적 화면입니다. 실제 인증·계정 조회·메일 발송·가입 처리는 없습니다. 제출 후 입력값을 지우고 미연동 안내를 표시합니다. README는 요청에 따라 0바이트로 유지합니다.

## 검증 결과

- Node 기본 테스트: 입력 경계, 이메일/아이디 형식, 비밀번호 확인, 지원하지 않는 폼 종류, 정적 자산 경로, 제출 차단, 배포 포함 확인
- 홈 및 계정 화면 4개 × 320/390/768/1024/1440px: 가로 넘침 없음
- 홈의 데스크톱/모바일 메뉴에서 로그인 진입
- 로그인 → 아이디 찾기/비밀번호 찾기/회원가입 및 복귀 링크 확인
- 빈 입력 오류와 첫 오류 초점, 이메일 오류, 비밀번호 불일치 확인
- 비밀번호 표시/숨기기, 제출 후 마스킹 복원 확인
- 네 폼의 유효한 테스트 입력 제출 후 미연동 안내·입력값 초기화·URL 쿼리 없음 확인
- 다시 입력하기 선택 시 초기화 및 첫 입력란 초점 확인
- 브라우저 오류·경고 없음, JavaScript 구문 검사 및 Git 공백 검사 통과

검증에는 가상 이름, `demo_user`, `demo@example.com`과 테스트용 문자열만 사용했습니다. 실제 계정이나 개인정보는 사용하지 않았습니다.

## API 연결 전 주의점

- 폼은 이벤트 처리기 연결 후에만 활성화됩니다. CSP의 `form-action 'none'` 및 `name` 없는 입력으로 기본 HTML 제출을 막습니다.
- 인증 코드에는 네트워크 요청·쿠키·웹 저장소·입력값 로그가 없습니다. 별도 `version.json` 요청은 배포 메타데이터만 조회합니다.
- 입력 제한은 UI 검토용입니다. 실제 비밀번호 정책, 중복 확인, 복구 절차는 #4의 서버 API 계약 확정 후 맞춥니다.
- 비밀번호 찾기는 요청 화면까지만 제공합니다. 본인 확인 없는 새 비밀번호 설정 화면은 제공하지 않습니다.
- 운영 반영 결과와 배포 커밋은 PR 본문에 갱신합니다.
